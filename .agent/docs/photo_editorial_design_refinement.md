# 写真記事エディター：誌面デザイン改善仕様（Codex向け）

## 目的
既存のPySide6写真記事エディターを維持しつつ、4フォーマットの視覚的完成度を実際の雑誌・新聞・写真集に近づける。**入力欄を増やすことより、既存の構造化記事データを活用したタイポグラフィ、視線誘導、写真と文章の組版改善を優先**する。

## 事前調査と制約
1. 既存のレンダラ、レイアウトモデル、フォント指定、文字サイズ、画像トリミング、プレビューとPNG出力の処理を調べ、変更計画を提示する。
2. 既存の4フォーマット、入力内容、写真の順序、プロフィール項目、出力機能を維持する。保存形式がある場合は後方互換を保つ。
3. `AGENTS.md` に従う。既存の `.venv` は変更せず、`uv sync` / `uv run` 等の自動変更を行わない。必要なら独立した検証環境を用いる。
4. 画像生成AIや外部ネットワークに依存しない。Qtの描画・テキスト計測機能を活用し、日本語フォントのフォールバックを考慮する。

## 共通のデザインシステム
- 各テンプレートに `DesignTokens` 相当の設定を設ける：ページ余白、列数とガター、色、罫線、見出し/本文/注釈のフォントファミリー・ウェイト・サイズ・行間、写真間隔、角丸の有無。
- 本文を基準に、主見出しはおおむね3〜5倍、サブタイトル1.5〜2倍、リード1.2〜1.4倍、キャプション0.8〜0.9倍を出発点とする。実際のサイズは文字数・利用可能領域を計測して調整する。
- 文字幅と改行位置を実測する。日本語見出しの不自然な一字残り、本文の欠落、写真や文字の重なりを避ける。タイトルが長い場合は2〜3行への改行、代替構図、段階的縮小の順に対応する。
- 強い視覚的階層（主役写真・見出し・リード・本文・補足情報）を設計する。全要素を同じサイズ・密度で並べない。
- 写真の縦横比と枚数に応じて構図を選択し、被写体の顔や重要部分を極力切らない。既存のトリミング指定があれば尊重する。
- 空白を無理に埋めず、文章が短い場合は「写真＋大きな見出し＋短い説明」の短文専用構図にする。長文では本文エリアを拡張し、可能ならページ分割する。テキストを黙って切り捨てない。
- 装飾は目的を持たせる。意味のない罫線、過剰なアクセントカラー、読めないほど小さい英字ラベルは避ける。

## 4フォーマットの個別改善

### 1. 雑誌特集型
- 現状の小さなタイトルと均等な写真配置を改善。日本語の大きな見出しを誌面の主役の一つにする。
- 少なくとも次の2構図：A) 横幅の広いヒーロー写真に可読性を確保して見出しを重ねる、B) 大きな見出し＋写真の左右非対称配置。
- カテゴリを短い特集ラベルとして表示し、リード文を本文から明確に分ける。小写真は大小をつける。
- 背景色や写真に重ねる文字はコントラストを検査し、必要なら半透明帯や配置変更を使う。

### 2. 新聞記事型
- 英語の新聞名より日本語の記事見出しが目立つようにする。新聞名・日付・号数等のマストヘッドは補助的な階層にする。
- 太めの日本語大見出し、サブ見出し、横罫線、2〜3段の本文組版、写真キャプションを実装する。
- 写真だけがページ下半分を占有しないよう、文章量に応じて写真と段組みの比率を調整する。
- 短文では新聞の「写真ニュース」構図、長文では段組み中心の「記事」構図に分ける。

### 3. フォトエッセイ型
- 小さすぎるタイトルを改善。余白を生かしつつ、大きな明朝系の日本語見出しを使用する。
- 少なくとも2構図：A) 1枚の大写真＋短い詩的な文章、B) 主写真＋補助写真を非対称配置したエッセイ。
- 写真キャプションや短い引用文を写真と視覚的に関連づける。本文を極端に小さくしない。
- 写真が主役であることを守り、飾りを増やしすぎない。

### 4. プロフィール特集型
- 現在の事務的な2列の表を主表現にしない。大きな名前・キャッチコピー・ポートレートを主役にする。
- プロフィール情報はラベルと値を読みやすいカード/区切り/アイコンなしの情報ブロック等で表現し、可変項目数に対応する。
- 少なくとも2構図：A) 大ポートレート＋右側に名前/プロフィール/紹介、B) 横断する名前見出し＋写真＋プロフィール帯＋記事。
- 小見出し付きの紹介文、引用文、補助写真を階層的に配置。個体紹介にも人物紹介にも使える中立的な装飾にする。
- 名前や項目が長い場合、項目数が多い場合も重なりや切り捨てを防ぐ。

## レイアウト選択とランダム性
- `format × content_density × photo_count/aspect_ratio` を考慮して候補を選ぶ。選択した構図名をUIに表示できるようにする。
- 同じ素材でも「別レイアウト」ボタンで構図を再生成。seed固定時は同じ結果になること。色やフォントだけのランダム変更ではなく、見出し位置・写真の大小・段組み等が変わること。
- 構図が成立しない場合は適切な代替構図へフォールバックする。

## UIと品質確認
- 既存の編集フォームは維持。必要に応じて「レイアウトを変更」「構図選択」「文字サイズ調整（任意）」を追加。UIの複雑化は最小限に。
- プレビューと書き出しで配置・改行・フォント・トリミングを一致させる。高解像度出力でも位置ずれしないよう論理座標で描画する。
- 各フォーマットについて、写真1/3/6枚、短文/標準/長文、短い/長いタイトル、日本語、プロフィール項目3/8個の代表ケースをテストする。該当しない組み合わせは除く。
- レイアウトの矩形衝突、本文欠落、ページ外描画、極端に小さい文字を検知できる範囲で自動テストを用意する。

## 実装順序
1. **Phase A：** 既存構成の調査と共通タイポグラフィ・テキスト計測・レイアウトトークンの整理。
2. **Phase B：** 雑誌と新聞のタイトル・本文・写真構図の改善。
3. **Phase C：** フォトエッセイとプロフィールの改善。
4. **Phase D：** 構図バリエーション、seed再現性、回帰テスト、プレビュー/出力一致の検証。

## 完了条件
- 4形式すべてで、現在よりも見出しの存在感と情報の階層が明確。
- 少なくとも各形式2構図が実際に異なるレイアウトとして動作。
- 既存の入力データと画像出力が引き続き動作し、写真・文章・プロフィール項目が欠落しない。
- 長い日本語タイトル、短文、写真枚数変化で著しい破綻がない。
- 変更したファイル、設計判断、テスト結果、残課題を報告する。

## Codexへの作業指示
最初に既存実装と本仕様の差分を整理し、変更対象ファイルとPhase A〜Dの実装計画を提示してください。計画を確認してから段階的に実装してください。単なるフォントサイズの一括変更ではなく、各フォーマットの構図そのものを改善してください。
